### 1.3. Математическая модель индекса боли (Pain Index)
Для объективного ранжирования проблем введена формула индекса боли:
$$\text{Pain Index (PI)} = N \times \bar{S} \times W_{\text{impact}}$$

Где:
* $N$ — абсолютная частота упоминания проблемы в сообщениях пользователей (Frequency).
* $\bar{S} \in [1.0, 5.0]$ — средняя эмоциональная интенсивность / ожесточение (Severity), рассчитанная по наличию ненормативной лексики, капслока, восклицательных знаков и лексических маркеров отчаяния/ярости (`пиздец`, `хуйня`, `заебал`, `верните`, `срочно`).
* $W_{\text{impact}}$ — вес критичности сбоя для стабильности платформы и удержания аудитории:
  * **3.0 (Финансовые потери и потеря доступа):** Пропажа реальных денег (Telegram Stars), сгорание шекелей, несрабатывание платных предметов (взятки).
  * **2.5 (Критические отказы системы):** Падения бота, недоставка постов, зависание клавиатур и команд.
  * **2.0 (Игровой баланс и токсичный грифинг):** Бесконтрольные грабежи заточками, пативэны, произвол автомутов.
  * **1.8 (Веб-интерфейс и инфраструктура):** Тормоза веб-версии, поломка скроллбара, сбои прикрепления медиа.
  * **1.2 – 1.3 (Предложения и хотелки):** Новые команды, кастомизация, мини-игры.

### 2.2. Причина возникновения дефекта в кодовой базе
Анализ `site_tgach/main.py` (строка 7195) и `common/database.py` (строки 6028-6044):
```python
# common/database.py
async def create_feedback(user_id: int, category: str, contact: str, message: str) -> bool:
    ...
    # Дедупликация: если тот же текст от того же юзера пришел менее 10 сек назад — отдавать True
    async with db.execute(
        "SELECT id FROM Feedback WHERE user_id = ? AND message = ? AND created_at > ? ORDER BY created_at DESC LIMIT 1",
        (user_id, message, now - 10.0)
    ) as cursor:
```
**Суть бага:** Разработчик осознал проблему дублирования позже и внедрил программную дедупликацию, однако:
1. Запросы от веб-клиента при отправке формы из-за отсутствия `disabled` на кнопке submit улетали параллельно двумя сокетами (HTTP pipelining / double click).
2. Транзакции выполнялись конкурентно (`BEGIN IMMEDIATE` захватывался по очереди, но проверка `SELECT id` попадала в зазор до фиксации первого коммита).
3. В схеме SQLite для таблицы `Feedback` напрочь отсутствует `UNIQUE(user_id, message, created_at)` или хэш-идентификатор идемпотентности.

### 2.3. Разбор болей веб-пользователей из фидбека
1. **Кастомный скроллбар (Feedback #3):** Переопределение нативных полос прокрутки через CSS/JS ломает кинетическую прокрутку, колесико мыши и тачпады. Пользователи выражают крайнюю агрессию.
2. **Ограничение оверборда только ОП-постами (Feedback #3):** Оверборд (главная лента) отображает только заглавные сообщения тредов, полностью игнорируя активные дискуссии и реплаи. Борда выглядит мертвой, если нет новых тредов.
3. **Требование JavaScript для чистого чтения (Feedback #3):** Контент не рендерится на сервере (SSR отсутствует), для просмотра текста принудительно исполняется SPA-бандл на клиенте.
4. **Критическая задержка ввода текста и отключение Undo (Feedback #7):** 
   - Скрипт маскота и визуальных эффектов держит CPU-поток занятым, из-за чего символы в `textarea` появляются с ощутимой задержкой (input lag).
   - Горячая клавиша `Ctrl+Z` перехвачена кривым кастомным обработчиком редактора, лишая пользователя базовой функции отмены ввода.

### 6.1. Детальные спецификации P0 (Critical Blockers)

#### FIX-P0-1: Надежная обработка платежей Telegram Stars
* **Проблема:** Потеря денег пользователем при краше или лаге бота во время покупки Stars (#420050).
* **Файлы:** `main.py`, `common/database.py`
* **Архитектурное решение:**
  1. Ввести таблицу `PendingStarTransactions (payment_charge_id TEXT PRIMARY KEY, user_id INT, amount INT, status TEXT, created_at REAL)`.
  2. Обработчик `pre_checkout_query` регистрирует запись со статусом `pending`.
  3. В `successful_payment` сначала фиксируется `status = 'completed'` в транзакции SQLite с начислением виртуальных благ, и только после этого отправляется подтверждающее сообщение.
  4. При рестарте бота запускается фоновый reconciler, который проверяет незавершенные транзакции.

#### FIX-P0-2: Исправление изоляции досок в логике Взятки (`cmd_bribe` и `/shop`)
* **Проблема:** Деньги за взятку списываются, но мут не снимается, если пользователь находится на другой доске (#513820).
* **Файлы:** `main.py` (строки 7349–7376 и 9216–9240)
* **Архитектурное решение:**
  1. Перед списанием проверять наличие мута **на всех досках**:
     ```python
     async with db.execute("SELECT board_id, mute_type FROM Mutes WHERE user_id = ? AND expires_at > ?", (user_id, time.time())) as cursor:
         user_mutes = await cursor.fetchall()
     if not user_mutes and not has_ram_shadow_mute(user_id):
         await message.answer("❌ Ты не находишься в муте ни на одной из досок!")
         return
     ```
  2. При успешной оплате взятки очищать муты **глобально по всем доскам**:
     ```python
     await db.execute("DELETE FROM Mutes WHERE user_id = ?", (user_id,))
     for b in board_data.values():
         b.get('mutes', {}).pop(user_id, None)
         b.get('shadow_mutes', {}).pop(user_id, None)
     ```

#### FIX-P0-3: Debounce и Cooldown для эскалации автомутов (Anti-Avalanche)
* **Проблема:** Приход 10 сообщений за 1 секунду раздувает мут с 5 минут до 700 минут из-за каскадного срабатывания прогрессии на каждом пакете (`GlobalLogs` 3570–3587).
* **Файлы:** `common/database.py` (функция `escalate_shadow_mute`, строки 2243–2255)
* **Архитектурное решение:**
  Ввести минимальный зазор (cooldown) между прогрессивными штрафами:
  ```python
  LAST_ESCALATION_TRACKER = {} # user_id -> last_escalation_ts
  
  if info['is_muted'] and is_exponential:
      last_esc = LAST_ESCALATION_TRACKER.get((user_id, board_id), 0.0)
      if now_ts - last_esc < 10.0:
          # Игнорировать сообщения, пришедшие в рамках той же серии флуда/пакета
          return info['expires_at']
      
      LAST_ESCALATION_TRACKER[(user_id, board_id)] = now_ts
      # Корректное увеличение срока
      ...
  ```

#### FIX-P0-4: Защита от краша при вызове `/wordcloud`
* **Проблема:** Бот предлагает команду в `/help`, а при вызове выбрасывает ошибку об отсутствии matplotlib (#514230).
* **Файлы:** `main.py`, `user_manager.py`
* **Архитектурное решение:**
  1. Если `HAS_WORDCLOUD` равен `False`, команда `/wordcloud` должна быть **скрыта** из меню `/help` и автокомплита команд Telegram Bot API (`set_my_commands`).
  2. При прямом вызове выдавать юмористический анонимный ответ без технических терминов («Архивариус пропил фломастеры, облако слов временно недоступно»).

#### FIX-P0-5: Идемпотентность сохранения фидбека
* **Проблема:** 100% обращений в таблице `Feedback` продублированы.
* **Файлы:** `site_tgach/main.py`, `common/database.py`
* **Архитектурное решение:**
  1. Добавить уникальный индекс в базу данных:
     `CREATE UNIQUE INDEX IF NOT EXISTS idx_feedback_dedup ON Feedback(user_id, message);`
  2. На фронтенде блокировать кнопку отправки формы (`btn.disabled = true; btn.innerText = "Отправка..."`).

### 6.2. Детальные спецификации P1 (Major UX & Balance Flaws)

#### FEAT-P1-1: Режим «Пацифист» (Самоотключение от PvP и экономики)
* **Обоснование:** Запрос #499123 и срыв #388669. Пользователи борды хотят читать и постить без страха быть ограбленными или замученными пативэном.
* **Механика:**
  1. Команда `/pacifist` или переключатель в профиле `/settings`.
  2. Пользователь в режиме Пацифиста получает статус `is_pacifist = 1` в таблице `Users`.
  3. **Иммунитеты:** Запрет применения к нему Заточки (`/rob`), Пативэна (`/partyvan`), Перцовки, Мут-гана, забрасывания говном (`/shit`, `/vomit`).
  4. **Ограничения:** Пацифист не может атаковать других игроков, не получает дропы шекелей и не участвует в рейтингах дуэлей.
  5. **Кулдаун на выход:** Переключение обратно занимает 24 часа для предотвращения абьюза во время атак.

#### FIX-P1-2: Защита системы жалоб от вендетт и спама (`/report`)
* **Обоснование:** 93.1% всех репортов генерируются двумя воюющими юзерами (`5264555563` и `5780136258`).
* **Механика:**
  1. Лимит: не более 1 репорта в 15 минут от одного `author_id` / `ip_hash`.
  2. Не более 3 репортов в сутки в сторону одного и того же автора.
  3. Введение штрафа: если 3 репорта подряд отклонены модератором как ложные, вызывающий получает автомут на команду `/report` на 24 часа.

#### FIX-P1-3: Обработка `edit_message_caption` для медиа-постов
* **Обоснование:** Жалоба #506402 («редакт на медиа не работает»).
* **Механика:**

  ```python
  @dp.edited_message(F.caption)

      # Обновление подписи в таблице Posts (поле text_content)

  ```

#### FIX-P1-4: Оптимизация веб-интерфейса и возврат Ctrl+Z
* **Обоснование:** Фидбек #7, #8 («текст вводится с опозданием, Ctrl+z не работает»).
* **Механика:**
  1. Вынести тяжелый рендеринг канваса маскота в Web Worker или добавить режим полного отключения его JS-цикла (не просто `display: none`, а `cancelAnimationFrame`).
  2. Удалить кастомный перехватчик сочетания клавиш `Ctrl+Z` в `textarea`, позволив браузеру использовать нативный стек undo/redo.
  3. Вернуть стандартный системный скроллбар в CSS (`scrollbar-width: auto; ::-webkit-scrollbar { display: initial; }`).

## 7. Заключение

Аудит показал, что сообщество DvachBot отличается высокой вовлеченностью, однако испытывает глубокое разочарование от накопившихся технических дефектов и токсичных игровых механик. 

**Ключевые точки фокуса для команды разработки:**
1. Немедленно устранить изоляцию досок в механике `/bribe`, прекратив списание средств за неработающие взятки (P0).
2. Внедрить debounce-фильтр в прогрессию автомутов, исключив многочасовые баны за микросекундные сетевые пакеты (P0).
3. Обеспечить режим «Пацифиста» для спокойных пользователей, защитив их от гриферов (P1).
4. Ограничить войну репортов и прекратить захламление админки параноидальными доносами (P1).

Все приведенные факты, расчеты и бэклог переданы руководству проекта для незамедлительного включения в спринт технических исправлений.
